# My Floorplan — v0.2 Closure & Next-Steps Plan

> **Goal:** Close the gap between the v0.2.x plan and actual implementation status. Identify what's done, what's missing, what's broken, and produce a concrete ordered task list to get the project to a coherent, working state.
>
> **Architecture:** Monorepo (pnpm workspaces) with `myfloorplan-web` (React + Konva + Babylon.js editor), `myfloorplan-api` (Cloudflare Worker + Hono + Drizzle + D1), `myfloorplan-shared` (TS types), and satellites (`assetcenter`, `admin`, `mobile`, `renderer`). Also present: `bathroom-viewer` (Three.js prototype, not part of monorepo) and `manufacturer-assets/` (GLB pipeline).
>
> **Tech Stack:** pnpm, TypeScript, Vite, React 18, Konva/react-konva, Babylon.js, Zustand, Hono, Drizzle ORM, Cloudflare Workers/D1/R2, Firebase Auth (dev bypass).

---

## 1. Where We Are — Status Summary

### v0.1 (Released ✅)
The foundation is solid:
- **myfloorplan-shared** — Full type system: `architecture`, `interior`, `environment`, `systems`, `properties` domains. Exports `FloorplanData`, `Floor`, `Project`, `Asset`, etc. Builds CJS/ESM + `.d.ts` via tsup.
- **myfloorplan-web** — Working 2D editor (Konva: walls, rooms, openings, placed items, grid snapping, ruler, pan/zoom, transformer) and 3D viewer (Babylon.js: arc-rotate camera, hemispheric + directional light, shadow generator, bloom/FXAA pipeline, ground plane). Zustand store with multi-floor support, project CRUD, auth store (Firebase anonymous + dev bypass), demo house loader. Full UI shell: Header, MiniNav, Sidebar, PropertiesPanel, EditorLayout.
- **myfloorplan-api** — Hono on Cloudflare Workers. Drizzle schema for 9 tables. REST routes: users/sync, projects CRUD, floorplan GET/PUT, assets GET (public), tags, asset-sources, asset-jobs, item-groups. Auth middleware (dev-token format). Health check probes D1 + R2.
- **myfloorplan-assetcenter** — React + Three.js asset browsing app scaffolded with crawler tools.
- **CI:** GitHub Actions for web, api, assetcenter, renderer, mobile.

### v0.2.x (Planned, ~15% complete 🟡)
The v0.2.x plan (docs/plan/v0.2.x.md) and progress doc (docs/progress/v0.2.md) exist but most items are unchecked. Reality is more nuanced — some things are partially done, some are missing entirely, and a few have subtle bugs.

## 3. Recommended Next Steps (Ordered)

### Phase A: Fix the broken integration (unblocks everything else)

**Task A1: Fix floorplan save/load shape mismatch**
- The API `PUT /projects/:id/floorplan` must accept and store the `floors` array, not just `data`.
- The API `GET /projects/:id/floorplan` must return `floors` (or keep backward compat with `data`).
- Decision needed: does the API store one `floorplans.data` JSON column that contains `{ floors: [...] }`, or do we add a separate `floors` table? The current schema has a single `floorplans` table with a `data` JSON column. The simplest fix: make `data` store `{ floors: [...] }` and have the API serialize/deserialize correctly.
- Files: `myfloorplan-api/src/index.ts:192-222`, `myfloorplan-web/src/store/useEditorStore.ts:323-391`

**Task A2: Implement debounced auto-save**
- Add a `useEffect` in the editor that debounces `saveCurrentProject()` (e.g. 2-second debounce after any store change to `wallLines`, `rooms`, `placedItems`).
- Files: `myfloorplan-web/src/store/useEditorStore.ts` or a new hook in `myfloorplan-web/src/lib/useAutoSave.ts`

**Task A3: Wire `POST /api/assets` (minimum viable)**
- At minimum: accept amultipart upload or URL registration, store metadata in `assets` table, return the created asset.
- Full R2 binary storage can be deferred, but the endpoint should not return 501.
- Files: `myfloorplan-api/src/index.ts:283-285`, `myfloorplan-api/src/db/schema.ts:27-41`

### Phase B: Editor completeness

**Task B1: Add floor selector UI widget**
- Dropdown or tab bar in the Header or MiniNav showing all floors with current indicator.
- Wires to `switchFloor(id)`.
- Files: `myfloorplan-web/src/components/layout/Header.tsx` or new `FloorSelector.tsx`

**Task B2: Implement undo/redo**
- Add `past: FloorplanData[]`, `future: FloorplanData[]` to the Zustand store.
- Wrap `addWallLine`, `updateWallLine`, `removeWallLine`, `addRoom`, `removeRoom`, `addPlacedItem`, `removePlacedItem`, `addWallOpening`, `removeWallOpening` to push to `past` and clear `future`.
- Add `undo()` / `redo()` actions and keyboard shortcuts (Cmd+Z / Cmd+Shift+Z).
- Files: `myfloorplan-web/src/store/useEditorStore.ts`

**Task B3: Add wall measurement labels in 2D**
- After rendering each `Wall2D`, show a text label with the wall length (in the current unit system).
- Files: `myfloorplan-web/src/components/floorplan/2d/Wall2D.tsx`

### Phase C: API hardening

**Task C1: Implement Firebase JWT verification**
- Add `jose` dependency to `myfloorplan-api`.
- Replace the `token_for_<uid>` dev bypass with real JWKS verification against the Firebase project's public keys.
- Keep a dev-mode override (env var) for local development without Firebase.
- Files: `myfloorplan-api/src/middleware/auth.ts`, `myfloorplan-api/package.json`

**Task C2: Align API response types with shared types**
- Ensure `createdAt`/`updatedAt` are serialized as ISO strings in API responses (D1 stores unix-ms).
- Ensure `floorplan.data` is properly `JSON.parse`d on read and `JSON.stringify`d on write.
- Files: `myfloorplan-api/src/index.ts`

**Task C3: Align `GET /api/assets` response with shared `Asset` type**
- Either extend the shared `Asset` type to include the joined fields, or strip them from the API response.
- Files: `myfloorplan-api/src/index.ts:226-275`, `myfloorplan-shared/src/types/index.ts:48-62`

### Phase D: Package completion (lower priority)

**Task D1: Scaffold myfloorplan-admin app shell**
- Vite + React + DaisyUI shell with auth guard, project nav, scraper log viewer placeholder.
- Files: `myfloorplan-admin/` (create `src/` tree)

**Task D2: Wire assetcenter to `/api/assets`**
- Replace mock/local data with real API calls to `GET /api/assets`.
- Files: `myfloorplan-assetcenter/src/`

**Task D3: myfloorplan-mobile Capacitor setup** (deferrable)
- `npx cap add android` + `npx cap add ios`, basic touch handlers for Konva stage.
- Files: `myfloorplan-mobile/`

### Phase E: Documentation cleanup

**Task E1: Update `docs/progress/v0.2.md`** to reflect actual current status.
**Task E2: Update `docs/TODO.md`** to cross-reference the v0.2.x plan or consolidate into one source of truth.

## 5. Risks & Open Questions

1. **Floorplan storage model:** The current schema has a single `floorplans` row per project with a `data` JSON column. The v0.2 plan talks about "multi-floor" but the schema doesn't have a separate `floors` table. Changing the storage model now (before production data exists) is safe, but it's a schema migration decision that affects the API, the store, and the shared types simultaneously.

2. **Unit system consistency:** The 2D editor uses a `calculateDistance()` that divides by 100 (line 374 of Floorplan2DView.tsx: "100px = 1 unit (m or ft)") — this is a hardcoded heuristic with no explicit unit system. The bathroom-viewer audit (docs/current-state.md) flagged this as a critical issue. The new editor should pick a unit convention (mm recommended) and stick to it.

3. **Firebase project config:** The `myfloorplan-web/src/lib/firebase.ts` file likely has hardcoded API keys or a demo config. Real JWT verification in the API needs the Firebase project ID to fetch JWKS. Check what's in that file before planning Task C1.

4. **bathroom-configurator vs myfloorplan-web:** These are two separate editors. The bathroom-configurator has tile/shower/surface features that the main editor doesn't have. If the intent is to merge them, that's a large architectural decision that should be planned separately. If they're meant to stay separate, the manufacturer asset pipeline (manufacturer-assets/) is the shared piece that needs coordination.

5. **D1 local development:** The API is designed for Cloudflare Workers (D1 + R2 bindings). Local dev uses Wrangler with simulated bindings. Verify that `wrangler.toml` and `.env.example` are sufficient for a new developer to run the API locally.
